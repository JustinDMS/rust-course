# Chapter 2: Programming a Guessing Game

--- card: read id=c01 xp=5 title="What we are building"
A tiny program: pick a secret number from 1 to 100, read guesses from the terminal, say *too small* or *too big*, and stop at the right answer.

Small as it is, it touches most of what the next chapters explain properly: `let` and `mut`, `String`, references, `match`, enums (`Ordering`, `Result`), `loop`, external crates, and the way Rust forces you to deal with things that can fail. The chapters after this one go deep; this one goes wide.

Here the game is a small library that you build in three stages, all editing the same file; each stage appends its own tests when you press Run. The `main.rs` that reads from the keyboard is shown at the end of the chapter, and a version that plays itself runs right in the browser.

--- card: read id=c02 xp=5 title="Reading a line of input"
```rust
use std::io;

let mut guess = String::new();
io::stdin()
    .read_line(&mut guess)
    .expect("Failed to read line");
```

Line by line:

- `use std::io;` brings the `io` module into scope so we can write `io::stdin()` instead of `std::io::stdin()`.
- `let mut guess = String::new();` makes an empty, growable, **mutable** string. Variables are immutable unless you say `mut`.
- `read_line(&mut guess)` appends what the user typed, newline included, to `guess`. The `&mut` passes a *mutable reference*: the function gets to change our string without taking it away from us. (Chapter 4 is all about this.)
- `read_line` returns a `Result`: either `Ok(bytes_read)` or `Err(error)`. `.expect("...")` says: if it is an `Err`, crash with this message; otherwise give me the `Ok` value. Ignoring a `Result` is a compiler warning, on purpose.

--- card: read id=c04 xp=5 title="Crates and Cargo.toml"
The standard library has no random number generator, so we add a crate from crates.io:

```toml
[dependencies]
rand = "0.10"
```

`"0.10"` is shorthand for `^0.10.0`: any version that is API-compatible with 0.10.0 (0.10.1, 0.10.7, but not 0.11). Cargo downloads it and everything it depends on, compiles them once, and writes the exact versions into `Cargo.lock`. Run `cargo update` when you want newer compatible versions.

Using it:

```rust
use rand::RngExt;   // the trait that provides random_range

let secret: u32 = rand::rng().random_range(1..=100);
```

`1..=100` is an inclusive range. `rand::rng()` gives a generator seeded by the OS; `random_range` comes from the `RngExt` trait, which is why it must be in scope.

The printed book uses rand 0.8, where this reads `rand::thread_rng().gen_range(1..=100)` with the `Rng` trait. Version 0.9 renamed those to `rand::rng()` and `random_range`, and 0.10 moved the method onto `RngExt`. Same idea each time; a change like that is exactly what a bump of the second number signals before 1.0, which is the next quiz.

Run it twice; the numbers change. The Playground has `rand` ready without a `Cargo.toml` because it pre-installs the most used crates. Note `let mut rng`: `random_range` changes the generator's internal state, so the variable must be mutable.

--- card: read id=c06 xp=5 title="match and Ordering"
Comparing two numbers gives one of three answers, and Rust spells that out as an enum:

```rust
use std::cmp::Ordering;

match guess.cmp(&secret) {
    Ordering::Less    => println!("Too small!"),
    Ordering::Greater => println!("Too big!"),
    Ordering::Equal   => println!("You win!"),
}
```

`cmp` takes a reference to the thing to compare against and returns an `Ordering`. `match` then checks the value against each **arm** in order and runs the first that fits. Leave an arm out and the compiler refuses: a `match` must be **exhaustive**. That one rule removes a whole category of "forgot the third case" bugs.

--- card: predict id=c07 xp=15 title="Which arm?"
```rust
use std::cmp::Ordering;

fn main() {
    let guess: u32 = 50;
    let secret: u32 = 37;
    let msg = match guess.cmp(&secret) {
        Ordering::Less => "Too small!",
        Ordering::Greater => "Too big!",
        Ordering::Equal => "You win!",
    };
    println!("{msg}");
}
```
? What is printed?
- [ ] `Too small!`
- [x] `Too big!`
- [ ] `You win!`
- [ ] Compile error: `match` cannot be used as a value
> `50.cmp(&37)` is `Greater`, so the second arm runs. `match` is an expression: each arm produces a value, and the whole thing becomes `msg`. All arms must produce the same type, here `&str`.

--- card: read id=c08 xp=5 title="From String to number, safely"
`guess` is a `String` and `secret` is a `u32`; Rust will not compare them. Convert:

```rust
let guess: u32 = match guess.trim().parse() {
    Ok(num) => num,
    Err(_) => continue,     // not a number: skip to the next loop iteration
};
```

Three things are happening:

- **Shadowing.** A new `guess` with a new type replaces the old one. Rust lets you reuse a name instead of inventing `guess_str` and `guess_num`.
- **`parse`** turns text into a number. It can fail, so it returns a `Result<u32, ParseIntError>`. The `: u32` on the `let` tells `parse` which number type to aim for.
- **Handling the `Err`** with `match` instead of `expect`. `_` means "whatever the error is, I don't care". `continue` jumps to the next iteration of the enclosing loop.

Chapter 9 returns to `Result` in depth. For now the pattern is: a `match` with an `Ok` arm and an `Err` arm.

> `parse` is strict: no surrounding whitespace, no inner spaces, and a `u32` cannot be negative. `trim()` first, then parse. The `::<u32>` "turbofish" is another way to say which type to parse into, instead of annotating the `let`.

--- card: read id=c10 xp=5 title="loop and break"
```rust
loop {
    // read, parse, compare ...
    match guess.cmp(&secret) {
        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),
        Ordering::Equal => {
            println!("You win!");
            break;
        }
    }
}
```

`loop` repeats forever until a `break`. An arm that needs more than one statement uses a block `{ ... }`. That is the whole program; the stages below rebuild it as testable pieces.

--- card: code id=c11 xp=5 title="Play it"
```rust
use rand::RngExt;
use std::cmp::Ordering;

fn parse_guess(input: &str) -> Option<u32> {
    match input.trim().parse() {
        Ok(n) => Some(n),
        Err(_) => None,
    }
}

fn main() {
    println!("Guess the number!");
    let secret: u32 = rand::rng().random_range(1..=100);

    // There is no keyboard on the Playground, so a scripted player stands
    // in: one bad input to show the message, then halving the range.
    let (mut low, mut high) = (1, 100);
    let mut first = true;

    loop {
        println!("Please input your guess.");
        let typed = if first { String::from("banana") } else { ((low + high) / 2).to_string() };
        first = false;
        println!("> {typed}");

        let Some(guess) = parse_guess(&typed) else {
            println!("Please type a number!");
            continue;
        };
        println!("You guessed: {guess}");

        match guess.cmp(&secret) {
            Ordering::Less => {
                println!("Too small!");
                low = guess + 1;
            }
            Ordering::Greater => {
                println!("Too big!");
                high = guess - 1;
            }
            Ordering::Equal => {
                println!("You win!");
                break;
            }
        }
    }
}
```
The whole game in one file, with your `parse_guess` from stage 1 and the `match` from stage 2. Run it a few times: the secret changes, and the scripted player never needs more than seven guesses. `let Some(guess) = ... else { ... }` is a `let`-`else`, which chapter 6 names properly: bind the value if the pattern fits, otherwise run the block, which must leave (`continue`, `return`, `break`).

--- card: read id=c14 xp=5 title="The real main.rs"
On a machine with a terminal, the same library is driven by this `main.rs`, which reads real guesses with `read_line`:

```rust
use guessing_game::{compare, feedback, parse_guess};
use rand::RngExt;
use std::cmp::Ordering;
use std::io;

fn main() {
    println!("Guess the number!");

    let secret_number: u32 = rand::rng().random_range(1..=100);

    loop {
        println!("Please input your guess.");

        let mut guess = String::new();
        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let Some(guess) = parse_guess(&guess) else {
            println!("Please type a number!");
            continue;
        };

        println!("You guessed: {guess}");

        let ordering = compare(guess, secret_number);
        println!("{}", feedback(ordering));
        if ordering == Ordering::Equal {
            break;
        }
    }
}
```

`use guessing_game::{...}` pulls the three functions in from the library crate of the same package; `main.rs` holds nothing but the loop and the I/O. That split, thin binary over testable library, comes back in chapter 12. The Playground cannot run this one because nothing is typing at it, but you now understand every line.
