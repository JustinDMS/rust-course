# Chapter 8: Common Collections

--- card: read id=c01 xp=5 title="Vec: a growable list"
A `Vec<T>` stores any number of values of one type, next to each other on the heap.

```rust
let mut v: Vec<i32> = Vec::new();   // empty; the type must be known somehow
v.push(5);
v.push(6);

let v2 = vec![1, 2, 3];              // the macro infers Vec<i32>
```

Reading an element, two ways:

```rust
let third: &i32 = &v2[2];            // panics if the index is out of range
let third: Option<&i32> = v2.get(2); // None if out of range
```

Use `[]` when an out-of-range index is a bug in your program; use `get` when it is a normal possibility (user input, searching).

Iterating:

```rust
for x in &v2 { println!("{x}"); }          // shared borrow of each element
for x in &mut v { *x += 10; }              // mutable borrow; `*` to reach the value
```

A `Vec` is dropped with its elements when it goes out of scope. The borrowing rules apply to the whole vector: holding a reference to one element while pushing is a compile error, because `push` may reallocate and move every element.

--- card: read id=c04 xp=5 title="One Vec, several kinds of thing"
Elements must be one type, but that type can be an enum:

```rust
enum Cell {
    Int(i64),
    Float(f64),
    Text(String),
}

let row = vec![
    Cell::Int(3),
    Cell::Text(String::from("blue")),
    Cell::Float(10.12),
];
```

A `match` on each element handles every variant. When the set of possible types is not known at compile time, that is what trait objects are for (chapter 18, beyond this course); within a known set, an enum is simpler and faster.

Other `Vec` methods you will reach for constantly: `len`, `is_empty`, `pop`, `insert`, `remove`, `contains`, `sort`, `sort_by_key`, `dedup`, `iter`, `extend`, `clear`, and `&v[a..b]` for a slice.

--- card: read id=c05 xp=5 title="String is UTF-8, and that changes things"
`String` is a `Vec<u8>` with the guarantee that the bytes are valid UTF-8. That guarantee makes some things easy and one thing impossible.

```rust
let mut s = String::from("foo");
s.push_str("bar");                 // append a &str
s.push('!');                       // append one char
let s2 = s + "baz";                // `+` takes the left String by value and a &str
let s3 = format!("{s2}-{}", 42);   // format! borrows everything
```

**You cannot index a `String` with an integer.** `s[0]` does not compile. In `"Здравствуйте"` each letter is two bytes; `s[0]` would be half a letter, so Rust does not offer it.

What you can do:

- `s.len()` is the length in **bytes**.
- `s.chars()` iterates Unicode scalar values; `s.chars().count()` counts them.
- `s.bytes()` iterates raw bytes.
- `&s[0..4]` slices by byte range, and **panics** if a boundary falls inside a character. Use it when you computed the indices from the string itself (as with `find`).
- `s.chars().nth(i)` fetches the i-th character, in O(n).

*Book: 8.2 "Storing UTF-8 Encoded Text with Strings"*

```rust
fn main() {
    let a = String::from("tic");
    let b = String::from("tac");

    println!("{a}");

```
? What happens?
- [ ] Prints `tic-tac tac` then `tic`
- [x] Compile error on the last line: `a` was moved by the `+`

--- card: read id=c08 xp=5 title="HashMap: keys to values"
```rust
use std::collections::HashMap;   // not in the prelude

let mut scores = HashMap::new();
scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Yellow"), 50);

let blue = scores.get("Blue").copied().unwrap_or(0);   // 10
for (team, score) in &scores { println!("{team}: {score}"); }   // arbitrary order
```

- `get` returns `Option<&V>`; `copied()` turns `Option<&i32>` into `Option<i32>`.
- Inserting a `String` key **moves** it into the map. Insert a reference and the map borrows, with the usual lifetime obligations.
- `insert` on an existing key **overwrites** the value.
- Iteration order is unspecified and changes between runs. Sort if you need a stable order.

The **entry API** is the idiom for "insert if missing, then update":

```rust
scores.entry(String::from("Blue")).or_insert(0);   // only inserts if absent

let count = map.entry(word).or_insert(0);          // &mut i32
*count += 1;                                        // deref to update in place
```

`or_insert` returns a mutable reference to the value, new or existing, so counting things is three lines. The default hasher is SipHash: resistant to denial-of-service attacks, not the fastest; swap it only when profiling says so.

*Book: 8.3 "Storing Keys with Associated Values in Hash Maps"*

--- card: predict id=c09 xp=15 title="Counting words"
```rust
use std::collections::HashMap;

fn main() {
    let text = "a b a c a b";
    let mut counts = HashMap::new();
    for word in text.split_whitespace() {
        let n = counts.entry(word).or_insert(0);
        *n += 1;
    }
    println!("{} {}", counts["a"], counts.get("z").is_none());
}
```
? What is printed?
- [x] `3 true`
- [ ] `3 false`
- [ ] `2 true`
- [ ] Compile error: cannot index a `HashMap` with `[]`
> `entry(word).or_insert(0)` gives `&mut i32` to the existing or freshly inserted count; `*n += 1` bumps it. `a` occurs three times. Indexing a map with `[]` works and panics on a missing key; `get` returns `None` for `"z"`.
