# Chapter 12: An I/O Project: Building a Command Line Program

--- card: read id=c01 xp=5 title="minigrep"
A small `grep`: given a search string and a file, print every line that contains the string.

```text
cargo run -p minigrep -- frog poem.txt
```

It brings together most of the course so far: ownership, `String` and `&str`, `Vec`, `Result` and `?`, structs with constructors, lifetimes, modules, and tests. The project lives in `projects/minigrep`. As with the guessing game, `main.rs` is complete and thin; the parts worth testing live in `lib.rs`, and that is where you work.

One difference from the book: our `run` **returns** the matching lines as a `Vec<String>` instead of printing them, and `main` does the printing. That keeps `run` testable without capturing stdout.

--- card: read id=c02 xp=5 title="Command line arguments"
```rust
use std::env;

let args: Vec<String> = env::args().collect();
```

`env::args()` returns an iterator over the arguments; `collect` gathers them into a vector. The first element is **the program's own path**, so the user's arguments start at index 1. (`env::args` panics on arguments that are not valid Unicode; `env::args_os` is the lossless alternative.)

With cargo, everything after `--` goes to your program rather than to cargo: `cargo run -p minigrep -- frog poem.txt` gives `args[1] == "frog"` and `args[2] == "poem.txt"`.

Reading a file is one call:

```rust
let contents = fs::read_to_string(file_path)?;
```

It returns `Result<String, io::Error>`, so `?` propagates a missing-file error to whoever can handle it.

--- card: read id=c04 xp=5 title="Separating concerns"
The first draft of any CLI is one `main` that does everything. The book's refactoring guidelines, which apply far beyond this project:

1. Split the program into `main.rs` and `lib.rs`; move the logic into the library.
2. `main` only parses arguments, calls `run`, and handles errors. It stays small enough to verify by reading.
3. Group configuration values into a struct (`Config { query, file_path, ignore_case }`) so their purpose is obvious.
4. Make the constructor return a `Result` with a descriptive error instead of panicking, and let `main` decide how to report it.

```rust
impl Config {
    pub fn build(args: &[String]) -> Result<Config, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }
        let query = args[1].clone();
        let file_path = args[2].clone();
        Ok(Config { query, file_path, ignore_case: false })
    }
}
```

The `clone()` calls are a deliberate trade: a little copying for a `Config` that owns its strings and has no lifetime to carry around. Chapter 13 removes them with iterators.

In `main`, errors become a message on stderr and a non-zero exit code:

```rust
let config = Config::build(&args).unwrap_or_else(|err| {
    eprintln!("Problem parsing arguments: {err}");
    process::exit(1);
});
```

`unwrap_or_else` takes a closure (chapter 13) that runs only on `Err`. `process::exit(1)` stops the program immediately, without the panic banner.

--- card: read id=c06 xp=5 title="Test-driven search"
The core function is written test-first: write a failing test, make it pass with the simplest code, then refine.

```rust
#[test]
fn one_result() {
    let query = "duct";
    let contents = "\
Rust:
safe, fast, productive.
Pick three.";
    assert_eq!(vec!["safe, fast, productive."], search(query, contents));
}
```

The signature needs a lifetime, because the result borrows from one of two inputs:

```rust
pub fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str>
```

The returned slices point into `contents`, never into `query`, and the annotation says exactly that. The body is a loop over `contents.lines()`, pushing each line that `contains(query)`.

The backslash after the opening quote of the test string tells Rust not to include the first newline; the content starts on the next line.

--- card: read id=c07 xp=5 title="Environment variables and stderr"
A case-insensitive mode, switched on by an environment variable rather than a flag:

```rust
let ignore_case = env::var("IGNORE_CASE").is_ok();
```

`env::var` returns a `Result`; we only care whether the variable is set at all. The case-insensitive search lowercases both the query and each line (`to_lowercase()` allocates a new `String`, so `contains` takes `&query`).

```text
IGNORE_CASE=1 cargo run -p minigrep -- to poem.txt     # bash
$env:IGNORE_CASE=1; cargo run -p minigrep -- to poem.txt   # PowerShell
```

Finally, errors should go to **stderr** so that `cargo run ... > output.txt` captures only real output. `println!` writes to stdout; `eprintln!` writes to stderr. `main` uses `eprintln!` for both the argument error and a failed `run`.

--- card: read id=c08 xp=5 title="Run it"
```text
cargo run -p minigrep -- body projects/minigrep/poem.txt
cargo run -p minigrep -- frog
cargo run -p minigrep -- frog nope.txt
```

The second and third commands should print one line of error to stderr and exit with status 1. On PowerShell, `$LASTEXITCODE` shows the status; on bash, `echo $?`.
