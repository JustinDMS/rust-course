# Chapter 5: Using Structs to Structure Related Data

--- card: read id=c01 xp=5 title="Defining and instantiating"
A **struct** names a group of related values and gives each one a name and a type.

```rust
struct User {
    active: bool,
    username: String,
    email: String,
    sign_in_count: u64,
}

let mut user1 = User {
    active: true,
    username: String::from("samus"),
    email: String::from("samus@example.com"),
    sign_in_count: 1,
};
user1.email = String::from("aran@example.com");   // needs `mut` on the binding
```

Every field must be given a value; there are no defaults unless you write them. Fields are accessed with a dot. Mutability is all or nothing: either the whole binding is `mut` or none of it is.

Two bits of sugar:

- **Field init shorthand**: when a variable has the same name as a field, `User { username, email, .. }` instead of `username: username`.
- **Struct update syntax**: `User { email: String::from("new"), ..user1 }` copies the remaining fields from `user1`. It *moves* the non-`Copy` ones, so `user1.username` is gone afterwards, but `user1.active` is still usable.

--- card: read id=c03 xp=5 title="Tuple structs and unit-like structs"
A **tuple struct** has a name but unnamed fields:

```rust
struct Color(i32, i32, i32);
struct Point(i32, i32, i32);

let black = Color(0, 0, 0);
let origin = Point(0, 0, 0);
```

`Color` and `Point` have the same shape but are different types: a function taking a `Color` will not accept a `Point`. That is the point. Fields are `black.0`, `black.1`, and the struct can be destructured: `let Point(x, y, z) = origin;`.

A **unit-like struct** has no fields at all: `struct AlwaysEqual;`. Useful when you need a type to implement a trait on but no data to store (chapter 10).

**Ownership of fields.** The examples use `String`, not `&str`, so each struct owns its data and is valid as long as the struct is. Storing a reference in a struct is possible but requires a *lifetime* annotation, which chapter 10 covers. Until then, structs own what they hold.

> A tuple struct is a brand-new type. `Feet` and `Meters` both wrap an `f64`, and that is exactly why they are useful: the compiler keeps them apart. This "newtype" pattern is everywhere in Rust code.

--- card: read id=c05 xp=5 title="Printing a struct: derive Debug"
`println!("{user1}")` does not compile: `String` and numbers know how to display themselves, a struct does not. The debug formatter `{:?}` is available for the asking:

```rust
#[derive(Debug)]
struct Rectangle { width: u32, height: u32 }

let rect = Rectangle { width: 30, height: 50 };
println!("{rect:?}");    // Rectangle { width: 30, height: 50 }
println!("{rect:#?}");   // pretty-printed over several lines
```

`#[derive(Debug)]` is an **attribute** that asks the compiler to generate the implementation. You will derive `Debug` on nearly every struct you write; it costs nothing at run time unless you use it.

`dbg!(expr)` prints the file, line, expression text and its value to **stderr**, and gives the value back, so you can wrap it around anything: `let w = dbg!(30 * scale);`. It takes ownership of its argument, so pass a reference for things you still need: `dbg!(&rect);`.

--- card: read id=c06 xp=5 title="Methods"
Functions that belong to a type go in an **`impl` block**. The first parameter is `self`, and the call syntax is `value.method()`.

```rust
impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }

    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }

    fn double(&mut self) {
        self.width *= 2;
        self.height *= 2;
    }
}
```

`&self` is short for `self: &Self`. Three flavours, same rules as any parameter:

- `&self`: borrow; read-only. The usual choice.
- `&mut self`: mutable borrow; the method changes the value. The caller's binding must be `mut`.
- `self`: take ownership; the value is consumed. Rare; used for transformations that turn the value into something else.

Rust adds `&`, `&mut` or `*` automatically when you call a method, so `rect.area()` works whether `rect` is a `Rectangle`, a `&Rectangle` or a `Box<Rectangle>`. A field and a method may share a name; `rect.width` is the field, `rect.width()` the method.

--- card: predict id=c07 xp=15 title="Which self?"
```rust
struct Counter { n: u32 }

impl Counter {
    fn bump(&mut self) { self.n += 1; }
    fn get(&self) -> u32 { self.n }
}

fn main() {
    let c = Counter { n: 0 };
    c.bump();
    println!("{}", c.get());
}
```
? What happens?
- [ ] Prints `1`
- [x] Compile error: cannot borrow `c` as mutable, as it is not declared as mutable
- [ ] Prints `0`
- [ ] Compile error: `bump` must return `Self`
> `bump` takes `&mut self`, so the binding it is called on must be `mut`: `let mut c`. The method signature tells callers everything about what the call may do to the value.

--- card: read id=c08 xp=5 title="Associated functions"
A function in an `impl` block **without** `self` is an *associated function*. It belongs to the type, not to a value, and is called with `::`:

```rust
impl Rectangle {
    fn square(size: u32) -> Self {
        Self { width: size, height: size }
    }
}

let sq = Rectangle::square(3);
```

`Self` inside an `impl` is an alias for the type. `String::from` and `Vec::new` are associated functions; constructors conventionally are called `new`, but there is nothing magic about the name.

A type may have several `impl` blocks. It makes no difference to the compiler; it is sometimes handy for grouping, and it is how generic and trait implementations are written later.

--- card: quiz id=c09 xp=10 title="Call syntax" multi
```rust
impl Rectangle {
    fn new(w: u32, h: u32) -> Self { Self { width: w, height: h } }
    fn area(&self) -> u32 { self.width * self.height }
}
```
? Which expressions are valid?
- [x] `Rectangle::new(2, 3)`
- [ ] `Rectangle.new(2, 3)`
- [x] `Rectangle::new(2, 3).area()`
- [x] `Rectangle::area(&Rectangle::new(2, 3))`
- [ ] `Rectangle::new(2, 3)::area()`
> Associated functions use `::` on the type. Methods are called on a value with `.`, and the automatic borrowing means `.area()` works on a temporary. The fully qualified form `Rectangle::area(&r)` is the same call written out, which is occasionally needed to disambiguate.
